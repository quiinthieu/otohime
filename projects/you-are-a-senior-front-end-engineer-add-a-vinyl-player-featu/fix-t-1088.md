# Fix plan: t-1088, the tonearm does not take a touch drag (pm-191, run-6463)

**Cause: code.** At delivery sha `0d3ac28`, which is also the deployed sha, a finger drag on the tonearm is taken by the browser as a pan. The arm gets `pointercancel` after two or three moves, the page scrolls, and nothing plays. `.tonearm { touch-action: none }` (`app/(vinyl)/vinyl.css:159`) has no effect: Chrome honours `touch-action` only on elements with a CSS box, and the arm is a `<g>` inside the turntable's `<svg>`. Evidence is in [qa-t-1088.md](qa-t-1088.md). Nothing else failed, and the pipeline is fine: no CI or environment change is needed.

## Change

1. **`app/(vinyl)/_components/turntable.tsx`**
   - Add a ref for the arm next to `svgRef` (line 68): `const armRef = useRef<SVGGElement>(null);`. Put `ref={armRef}` on the `<g className="tonearm"` (line 204).
   - Add an effect that registers a native, non-passive `touchstart` listener on the arm. React's `onTouchStart` is passive, so it cannot be used. Removing the listener in the cleanup keeps "every listener released on unmount" true. Roughly:

     ```ts
     useEffect(() => {
       const el = armRef.current;
       if (!el) return;
       // touch-action does not apply inside an <svg>, so stop the pan here: a finger on the arm drags it.
       const hold = (e: TouchEvent) => {
         if (e.cancelable) e.preventDefault();
       };
       el.addEventListener("touchstart", hold, { passive: false });
       return () => el.removeEventListener("touchstart", hold);
     }, []);
     ```

     (`useEffect` joins the react import on line 3.) I proved `touchstart` and `touchmove` both work in Chrome: 0 `pointercancel`, 0 scroll, phase `playing`. Prefer `touchstart`: iOS Safari decides on panning at touchstart. `onPointerDown` already calls `focus()`, so a tap still focuses the arm.
   - Fix the comment at the top (lines 11–20): touch works because of this listener, not because of `touch-action`.
2. **`app/(vinyl)/vinyl.css:159`**: keep `touch-action: none` on `.tonearm`. It is harmless, and the walk's "only on the tonearm" check reads it. Edit the comment to say the listener does the work inside the SVG.
3. **`README.md`**, in the "Dragging and scrubbing" paragraph: replace "only the tonearm has `touch-action: none`" with "a finger on the tonearm drags it (a non-passive touchstart listener stops the page panning; `touch-action` does not apply inside an SVG)".
4. **Regression guard in `scripts/walk-vinyl.sh`**, beside the touch-action check at line 202: a static check that `app/(vinyl)/_components/turntable.tsx` contains `addEventListener("touchstart"` and `passive: false`. The served HTML cannot show this.

Do not change the player, `playerVars` or the sleeve drag; they pass.
