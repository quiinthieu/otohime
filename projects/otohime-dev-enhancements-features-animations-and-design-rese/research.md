# Research: otohime.dev enhancements, twelve ideas (pm-242, run-8308)

**Idea.** Twelve enhancements for otohime.dev gathered from X and Dribbble: a boot intro, an ink-wipe theme switch, zoom page transitions, a live pipeline doodle, a mini-game in the pocket console, chiptune UI sounds, a 3D console tilt, richer hand-drawn modes, a Now Playing widget, a scroll-drawn Sketches gallery, a drag-a-cable switchboard and cartridge project cards. Each as a separate, small, incremental change; reduced motion respected; the paper-and-ink pocket-console style kept.

**Short answer.** Checked against the repo at **702c5dd** (the live site reported cc52f9e, one commit behind). Two of the twelve already exist: **idea 2 (ink wipe) is shipped** as `ink-spread` in `components/theme-toggle.tsx` and needs no build task, and **idea 11 (switchboard) is three quarters built**: only the drag is new. Idea 1's boot exists in miniature (the LCD boots with `.boot`/`.splash`); the idea is a first-visit/returning-visit split, **without GSAP**: README §Motion forbids a motion library, and everything here is CSS keyframes, React 19.3's stable `<ViewTransition>` (react.dev, 2026-09-09) and one small island each. Ten build tasks remain, and they slice into **S tasks that need nothing** (6 sounds, 7 tilt, 8 ink modes, 11 drag plug, 12 cartridges), **M tasks that build on those** (1 boot, 3 zoom transition, 4 pipeline, 5 game) and **two with outside dependencies** (9 Now Playing needs Spotify Premium plus an operator chore for secrets; 10 Sketches must follow pm-240, which is rewriting `/sketches` right now). Three house constraints shape every one of them: the figures run **on twos (12 fps) from pure reducers in `lib/machines.ts`**, so each new figure is a tested reducer first; **the resting pose is the base style**, so every animation runs *from* somewhere and a still is the whole drawing; and `lib/motion.test.ts` plus `scripts/probe-motion.sh` pin the layout wrappers, the `@view-transition` rule and the 11 `main li.rise` rows on `/projects`. Collision watch: pm-241 (footer) and pm-240 (portraits) are both landing in `content/site.ts`, `globals.css`, `components/switchboard.tsx` and `/sketches`; tasks here should add, not rewrite, and rebase.

## 2. The twelve, one by one

Each: what exists, the design, files, size, verification, risks. "Reducer" means a pure `(state, action) => state` with `tick`/`settle`, tested with `node --test`.

### 2.1 Boot-up cartridge intro (animation) — **S/M**, after 2.6 if the chime is wanted

- **Exists:** the LCD already boots: power lamp at 0.7 s, LCD at 0.8 s, `OTOHIME` splash for 1.6 s, menu at 1.6 s, on every visit.
- **Design:** keep the boot *inside the console* (a full-screen overlay would hide the entrance, fight the hop's `pagereveal` crossfade and break "the still is the whole drawing"). First visit in a session: `flicker` (`steps(1)`, opacity 0/1/0/1 over 0.3 s) on the LCD, a scan sweep (a `fig-paper` rect translating down, `steps(8)`), the splash with a `print` reveal, the cartridge clicking in (`translateY(-3px → 0)`, 210 ms), the chime if sound is on. Returning in the same session (`sessionStorage["console:booted"]`): the menu is on at 0 s, applied **before paint** with the `pinTheme` trick: one more inline statement in `app/(site)/layout.tsx` sets `data-booted` on `<html>`, and `:root[data-booted] .boot, :root[data-booted] .splash { animation-duration: 0.01ms }`; the island writes the key on the splash's `animationend`. No layout shift, no hydration mismatch (`suppressHydrationWarning` already covers script-set attributes).
- **Chime:** browsers block audio before a gesture, so the chime only sounds when sound is on (2.6) **and** the boot starts after a gesture in this document (coming back to `/` via the masthead or the sidebar). On a cold load it is silent. Say so in the task.
- **Files:** `components/handheld.tsx` (classes, the `animationend` effect), `app/(site)/layout.tsx` (+1 inline statement), `globals.css` (`flicker`, `scan`; the reduced-motion block stays last), `lib/boot.ts` + test (the sequence as data: part, delay, duration; a test pins total ≤ 2.4 s and that every part animates *from* hidden to the resting pose).
- **Verify:** probe at 1366×768 and 390×844: first load runs a 1.6 s `splash`; after `location.reload()` the LCD's animations are empty or finished and `sessionStorage["console:booted"] === "1"`; under reduced motion all ≤ 1 ms; the menu is in the HTML without JS; `scripts/probe-motion.sh` green.
- **Risk:** `sessionStorage` blocked (Safari private, policy): wrap in `try`, boot fully every time.

### 2.3 Zoom-into-screen page transitions (animation) — **M**, after 2.1

- **Exists:** `page-in`/`page-out` fades (150 ms out, 210 ms in), `nav-current` slides, `masthead` pinned; React 19.3's `<ViewTransition>` is stable and already imported from `react` everywhere.
- **Design, two layers.** (a) **The label morphs into the title.** React pairs a `name`d `<ViewTransition>` in the removed subtree with one in the inserted subtree in the same Transition ("share"). Chromium does not document `view-transition-name` on SVG `<text>` inside a filtered `<g>`, so do not name SVG: on A the console renders the chosen label as a small **HTML** `<output>` positioned over the LCD line (percentages of the viewBox, which hold as the SVG scales) wrapped in `<ViewTransition name="page-title" share="zoom">`; `FigTitle`'s `h1` on every `(app)` page gets the same wrapper (one page mounts at a time, so the name stays unique). (b) **The page zooms out of the screen.** The island writes the LCD's rect centre into `--zx/--zy` on `<html>` (the `--tx/--ty` pattern), then `startTransition(() => { addTransitionType("console"); router.push(href) })`; the `(app)` layout wrapper and pages take `enter={{ console: "zoom-in", default: "page-in" }}`, and `::view-transition-new(.zoom-in)` animates `scale(0.04) → 1` from `transform-origin: var(--zx) var(--zy)`, 320 ms on the house curve, over the existing fade. Chromium 125+ for types (the Next guide's note); elsewhere the fade runs. Reference: `node_modules/next/dist/docs/01-app/02-guides/view-transitions.md`, Steps 1 and 3.
- **Pairing:** the destination must render in the same commit; the sr-only `<Link>` list prefetches all six static pages, and the `(app)` layout's `Nav` sits behind `Suspense` with a static fallback, so the pair forms.
- **Files:** `components/handheld.tsx`, `components/figures.tsx` (`FigTitle` wrapper), the `(app)` layout and pages (an `enter` object), `globals.css`, `lib/motion.test.ts` (allow the typed `enter`), `scripts/probe-motion.mjs` (its `/ → /work (the console)` check expects a plain fade and must accept the zoom).
- **Verify:** probe: press A on `/`, `document.getAnimations()` during the transition contains an animation on `::view-transition-new(.zoom-in)` and a group for `page-title`; the destination's `h1` text equals the console label; keyboard Enter does the same; under reduced motion zero-length; `/work → /` (masthead) still fades. `lib/motion.test.ts` green.
- **Risk:** React warns if two `name="page-title"` are mounted at once (the overlay exists only during the press, never with an `(app)` page). Safari may skip typed classes: the fade remains.

### 2.4 Live data-pipeline doodle on Work (feature) — **L → split S + M**

- **Exists:** `Conveyor` tells "extract, carry, load"; `ServerRack` runs the nightly job. The idea adds the shape of the whole system: source → queue → warehouse → dashboard.
- **Design:** `Pipeline`, a `Machine` (viewBox ~`0 0 460 300`): four isometric `box()`es on one ground: a **source** (squat box with a disk lid), a **queue** (long low box with a slot row), a **warehouse** (tall box with shelves) and a **dashboard** (a monitor with three `fig-lcd` bars), joined by pipes (ink edge + `fig-metal`, like the conveyor legs). **Packets** are small `fig-top` squares riding the pipes on twos. Reducer `pipeline` in `lib/machines.ts`: state `{ packets: {id, leg, t}[], queued, stored, shown, paused, t }`; actions `emit`, `backfill` (a burst of 8, spaced 3 frames), `pause`/`resume` (packets pile up in the queue and drain: the lag story), `tick`, `settle`. Stats: In flight, In the queue, Rows stored, Dashboard lag. Words in `content/site.ts`. The figure rests until pressed; an optional "Live" chip starts a trickle (a packet per 24 frames) that stops when hidden; a flowing pipeline loops in life, so it passes the README test, but default **off**.
- **Placement:** `Pipeline` becomes the hero under the intro; `Conveyor` moves beside the Stack with `ServerRack` below. Recommend keeping all three (additive, reversible) and letting the owner judge the page.
- **Files:** `lib/machines.ts` + `lib/machines.test.ts` (engine, S: packets never skip a leg, pause holds them in the queue, backfill emits 8, settle lands everything, stats add up), `components/pipeline.tsx` + `work/page.tsx` + `content/site.ts` words (M).
- **Verify:** unit tests; probe: press Backfill, `data-busy` set, 12 fps ticks, rests within 10 s; reduced motion: press lands at rest in one dispatch; no animation inside the filter other than the 12 fps re-render (same cost class as the conveyor).
- **Risk:** three filtered SVGs on `/work`; each rasterises its filter once at rest, so fine; avoid any 60 fps CSS loop inside `Inked`.

### 2.5 Mini-game in Pocket (feature) — **L → split S/M + M**, after 2.6 for the beeps

- **Design: "Pipeline snake."** On the menu, **B** (drawn, inert today) opens the game on the LCD: a 16×14 grid of 4-unit cells fills the 64×56 LCD exactly. The snake is a pipe, food an event packet; eating grows the pipe and scores a row; walls and the pipe itself end the run with `PIPE BURST`; the high score lives in `localStorage["pocket:high"]`. Speed: a cell every 2 ticks, one tick faster every 5 packets, floor 1. Controls: `▲ ▼ ◀ ▶` chips (the d-pad gets lit left/right arms), arrow keys at `scrollY 0` as today, A = start/restart, B = menu. Reducer `snake` in `lib/snake.ts` with a seeded `mulberry32` (as in vinyl's crackle) so food placement is deterministic in tests; `pad` gains `left`, `right`, `b` and `mode: "menu" | "game"`.
- **Konami:** typed on the d-pad and A/B **inside the console** (`↑↑↓↓◀▶◀▶ B A` as pad actions, matched by a pure prefix matcher): unlocks `DEBUG MODE` (walls wrap) and writes `localStorage["pocket:achievement"]`. It is not a `window` listener (pm-241's footer owns that, and the two could both be live on a tall viewport), and it never touches `end:achievement`.
- **Reduced motion:** the game becomes **turn-based**: no `useTick`; each direction press advances one cell. Same reducer, same tests.
- **Accessibility:** the LCD is decorative; the `aria-live` readout says the score and state; chips are labelled buttons; the sr-only menu links stay.
- **Files:** `lib/snake.ts` + test (S/M: growth, collisions, wrap in debug, seeded food never lands on the pipe, speed table), `lib/machines.ts` (`pad` additions), `components/handheld.tsx` (screen, d-pad arms, B, storage via `useSyncExternalStore`), `globals.css` (`.lcd-cell`), `lib/pages.test.ts` untouched (the menu stays six lines).
- **Verify:** unit tests; probe: press B then A, cells render, score changes on a food, high score survives reload, reduced motion advances only on key press; `e2e/rbac.test.ts` unchanged.
- **Risk:** rendering 224 cells as `<rect>`s inside the filter at 6 Hz; draw only the pipe and the food (≤ 60 rects), which is what the LCD classes already do for the menu.

### 2.6 Chiptune UI sounds + mute toggle (feature) — **S**, no dependencies, unblocks 2.1 and 2.5

- **Design:** `lib/sound.ts` (pure, tested): a note table (`move` 880 Hz 30 ms, `open` 1320→1760 Hz 80 ms, `back`, `chime` C5 E5 G5 at 90 ms each, `eat`, `burst`), a square-wave envelope (attack 2 ms, decay to 0) and the gain (−18 dB cap, like `crackleGain`). `lib/sound-client.ts`: one `AudioContext` created lazily **inside a gesture** (the vinyl rule), `OscillatorNode` square + `GainNode`, `close()` on `pagehide`. Off by default; the toggle is a speaker `icon-btn` beside `ThemeToggle` in `components/masthead.tsx`, `aria-pressed`, persisted in `localStorage.sound` via `useSyncExternalStore` with a `null` server snapshot. The console beeps on ▲▼ and A; the claw and switchboard can follow.
- **Verify:** unit tests for the table and envelope; probe: no `AudioContext` constructed before a gesture (patch the constructor), one after toggling on and pressing A, none when off; the toggle survives reload; no console error with autoplay blocked.
- **Risk:** the masthead is shared by every site page, so the button must not shift the layout (a fixed `size-4` icon).

### 2.7 3D console tilt/parallax (animation) — **S** (not M), no dependencies

- **Design:** the console is a fixed isometric projection, so "rotate" means a CSS 3D tilt of the whole figure, not re-projection. On `(hover: hover) and (prefers-reduced-motion: no-preference)` the island maps pointer position over `.machine-figure` to `--rx/--ry` (±6°), applied as `transform: perspective(900px) rotateX(var(--ry)) rotateY(var(--rx))` on the `<svg>` with `will-change: transform` (the filter rasterises once; the tilt is a composited transform), and `transition: transform 400ms cubic-bezier(0.16,1,0.3,1)` so it springs back on leave. The `fig-shade` shadow shifts the other way (`translate` on the shadow group) for depth. Gyroscope: skipped (iOS needs a permission prompt inside a gesture; `(hover: none)` devices simply get no tilt). Drag-rotate: skipped (an isometric drawing has no back faces).
- **Files:** `components/machine.tsx` (an optional `tilt` prop; the Handheld opts in), `globals.css`.
- **Verify:** probe: moving the pointer changes the computed `transform`; leaving returns to `none` within 500 ms; under reduced motion and at 390×844 (touch) the transform stays `none`; the boot and press animations still run inside.

### 2.8 Richer hand-drawn modes (design) — **S/M**, no dependencies

- **Exists:** `Inked` = one filter (`feTurbulence` seed 3 → `feDisplacementMap scale={wobble}`, plus riso grain), the wobble slider 0–7 and the swatches in `.machine-knobs`.
- **Design:** a "Hand" picker (**ink** default, **pencil**, **crayon**, **watercolour**) and a **Re-roll** chip. `lib/ink-modes.ts` (pure, tested) maps a mode to filter parameters: pencil = stroke 1.4, turbulence 0.08 at scale ×0.6, a second displaced copy at 40 % (the double line); crayon = stroke 3.2, turbulence 0.02 at ×1.4, heavy grain; watercolour = fills through `feGaussianBlur 1.2` and lightened, strokes crisp via a second `feMerge` pass. `Inked` gains optional `mode` and `seed` props (defaults unchanged, so every figure, test and probe is untouched). **Re-roll** bumps the seed; **boiling lines** cycle it every 2 frames with `useTick` while a `Boil` chip is on (the filter re-rasterises at 6 Hz: one figure at a time, motion-on only). Per-figure state like the swatches, not persisted.
- **Verify:** unit tests on the table (strokes within 1–4, seeds distinct, default equals today's values); probe: switching modes changes the filter attributes; `Boil` on → `seed` changes at ~6 Hz, off → stops; reduced motion → the chip is disabled.
- **Risk:** Firefox renders `feDisplacementMap` slowly on large SVGs; the modes keep the same primitive count, so no regression beyond today's.

### 2.9 Now Playing widget (feature) — **M → split S/M + S**, operator chores

So: a dev-mode app for one user. Secrets `SPOTIFY_CLIENT_ID/SECRET/REFRESH_TOKEN` (one-time Authorization Code grant, `user-read-currently-playing user-read-recently-played`). **Current game:** Spotify has none; Steam's `GetPlayerSummaries` returns `gameextrainfo` for a public profile with `STEAM_API_KEY` + SteamID64. Keep `expire ≥ 300`: the caching doc makes anything shorter a dynamic hole instead of part of the static shell. Behind `<Suspense fallback={<Cassette quiet />}>` so no-JS visitors get the quiet face. ### 2.10 Scroll-drawn Sketches gallery (animation) — **M**, **after pm-240 closes**

- **Facts:** the art is raster (JPEG studies; pm-240's PNG portraits), so nothing in it can be stroke-drawn; `animation-timeline: view()` is in Chromium since 115 and Safari since 26 (Sept 2025), Firefox behind a flag (Interop 2026 target) → progressive enhancement under `@supports (animation-timeline: view())`.
- **Design:** each `<figure>` gets (a) an **inked frame**: a rough rectangle path (`pathLength="1"`, `stroke-dashoffset 1 → 0`) in a small unfiltered SVG overlay, drawn on with `animation-timeline: view(); animation-range: entry 10% cover 45%`, and (b) a **paper wash**: a paper-coloured sheet over the image that slides off (`translateX`, compositor-only) over the same range, so the picture is "painted" as it rises into view; the caption fades up last. Everything rests complete without `@supports`, without JS and under reduced motion. **Reduced motion:** scroll timelines ignore `animation-duration`, so the global block adds `animation: none !important` for the sheet classes (else the probe's "≤ 1 ms or finished" check sees a live scroll animation). Keep pm-240's `Sheet` markup; wrap, do not restructure.
- **Files:** `app/(site)/(app)/sketches/page.tsx` (`Sheet` only), `globals.css`, `scripts/probe-sketches.mjs` (pm-240's probe; add the scroll checks).
- **Verify:** probe at 1366 and 390: before scroll the first sheet below the fold has `currentTime 0` on its `wash`; after scrolling it into view the wash's `transform` is off-sheet and the frame's `stroke-dashoffset` is 0; under reduced motion `getAnimations()` on the sheets is empty; in a `@supports`-negative run (inject a stylesheet override) the page shows every picture at rest.
- **Risk:** `filter`/`clip-path` on scroll timelines repaint every frame; stay on `transform`/`opacity` and the tiny frame path.
