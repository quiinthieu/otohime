## 1. Product Outcome

Deliver two paper-and-ink experiments on `otohime.dev`:

1. **Susuki Field Footer (`components/susuki-field.tsx`, `components/susuki-field-loader.tsx`, `lib/susuki.ts`)**:
   - An ambient WebGL2 instanced field of 6,000–10,000 sumi-ink pampas grass (*susuki*) blades with fuzzy plume tips mounted as a client backdrop island in `components/end-footer.tsx`.
   - Cursor movement parts nearby blades like a wind gust via a critically-damped CPU spring (`uPointer`, `uPointerVel`); page scroll velocity (`scroll` listener, low-passed and clamped) accelerates ambient wind speed and sway amplitude.
   - Season tinting (`uTint`) follows `<html data-season>` (`spring`, `summer`, `autumn`, `winter`) and light/dark scheme (`data-theme` / `prefers-color-scheme`) using the same `MutationObserver` + `useSyncExternalStore` pattern as `components/season-layer.tsx`.
   - After 12–20s of pointer/scroll/key inactivity (or immediately when triggered via a deterministic test hook `data-susuki-fox-trigger` / `window.__triggerSusukiFox`), a baked sumi-ink fox silhouette trots across the field once per session, parting blades along its path and retreating immediately on any user input.
   - Under `prefers-reduced-motion: reduce`, `Save-Data`, missing WebGL2, or `webglcontextlost` (handled with `preventDefault()` and restored on `webglcontextrestored`), the canvas draws one static frame with zero `requestAnimationFrame` loop, zero gust displacement, and no fox animation.
   - Preserves every existing `EndFooter` invariant enforced by `scripts/walk-end.sh`, `scripts/probe-end.mjs`, `scripts/probe-end-dom.mjs`, and `e2e/bottle-ui.test.ts`: `EndFooter` stays a Server Component, `footer.end` keeps exactly 5 `<svg>` elements (`endSvgStructure`), `[data-end-waterline]` stays `footer.lastElementChild`, the canvas is `aria-hidden="true"` and `pointer-events: none` (with pointer events tracked passively on `footer.end` so all links and controls stay clickable), and reserved footer/stage/Bottle geometry shifts `0 px`.

2. **Ink Shelf (`/shelf` — `app/(site)/(app)/shelf/page.tsx`, `components/ink-shelf.tsx`, `components/ink-shelf-3d.tsx`, `lib/shelf.ts`, `lib/shelf-shader.ts`)**:
   - A Server Component route at `/shelf` that assembles a deterministic shelf of up to 40 volumes from `site.projectList` and `site.notes` (newest left, 3–4 wooden shelf rows, spine width/height/tilt and page-count thickness derived deterministically from slug and content length).
   - Always renders a crawlable, keyboard-accessible `<ul>` of real `<Link>`/`<a>` items and a flat CSS/washi shelf fallback in the DOM for assistive tech, SSR, `Save-Data`, and no-WebGL environments, plus a discovery link to `/shelf` on `/projects`.
   - Lazy-loads the Three.js 3D bookshelf (`components/ink-shelf-3d.tsx` via `next/dynamic(..., { ssr: false })`) so `three`, `@react-three/fiber`, and `@react-three/drei` load only on `/shelf`.
   - Renders 3–4 rows of 3D box volumes on wooden planks with procedural 2D-canvas spine typography (no external font fetch), low-FOV camera with pointer parallax, raycast hover spring lift, and synchronized 3D book highlight when keyboard focus moves through the accessible DOM links.
   - Applies a custom WebGLRenderer GLSL post-process pass (colour + depth FBO and view-space normal FBO):
     - Sobel / Roberts-cross edge detection on linearized depth and view-space normals (`edge = max(kd * depthEdge, kn * normalEdge)`).
     - **Grazing-angle fix**: computes `ndv = abs(dot(N, V))` and scales the depth edge threshold by `1 / max(ndv, 0.2)` (or suppresses depth edges when `ndv < 0.2`) so steep-angle shelf planks and book tops never trigger false depth silhouettes.
     - Modulates stroke weight with hash/brush noise and slight UV wobble, and composites paper colour × 3-tone cel shading × 3–4 band procedural object-space tonal hatching (preventing the screen-space shower-door effect under parallax).
     - Exposes deterministic threshold uniforms and a query flag (`?outlineDebug=1`) for inspecting edge/hatching passes, caps DPR at `1.5`, and uses `frameloop="demand"` when idle.
   - Clicking a 3D book (or activating its accessible link) positions a DOM transition proxy over the book's projected screen bounding box (`Vector3.project`) with a unique `view-transition-name` (`project-<slug>` for projects matching existing `h1 { view-transition-name: project-<slug> }` rules across all 11 project stylesheets, and `note-<slug>` for notes paired with `app/(site)/(app)/notes/[slug]/page.tsx`) and navigates via `document.startViewTransition` (skipped cleanly under `prefers-reduced-motion: reduce`).
