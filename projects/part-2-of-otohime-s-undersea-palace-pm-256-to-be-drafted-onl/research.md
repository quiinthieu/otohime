## Recommended design

### Backend: Cloudflare Worker + Durable Object, pure fan-out
- One Worker, one DO class `GhostRoom`, `idFromName(room)` where room is the page path (`/` or `/ryugu`). SQLite-backed DO (the only kind on the Free plan; nothing is written to storage). Hibernatable WebSockets (`acceptWebSocket`, `webSocketMessage`, `webSocketClose`), so an idle room costs nothing; incoming messages bill at 20:1, outgoing free. Free plan: 100k requests/day, 13k GB-s/day, far above this site's traffic.
- Upgrade handling in the Worker: reject unless `Upgrade: websocket`, `Origin` in `ALLOWED_ORIGINS` (wrangler var, comma list, `https://otohime.dev`), room path in an allowlist. 403/404 otherwise. No cookies, no IP/UA read or logged; `observability.logs` disabled in `wrangler.jsonc`.
- Protocol (JSON, tiny): client→server `{t:"m",x,y}` and `{t:"c",x,y}` with x,y normalized 0..1 (clamped server-side, NaN dropped); server→client `{t:"hi",id,n}`, `{t:"m",id,x,y}`, `{t:"c",id,x,y}`, `{t:"bye",id}`, `{t:"n",n}` on join/leave, `{t:"full"}` then close 1013 when the room is at cap. ids are `crypto.randomUUID().slice(0,8)` per connection, never reused across connections. Caps: 24 ghosts per room; >15 messages/s per connection dropped (token bucket); message >128 bytes dropped; a connection with 5 bad frames closed 1008. Immediate fan-out to the other sockets (no batching tick: simple over clever; with a 10 Hz client cap and 24 ghosts the worst case is bounded and rare; a 10 Hz batch is a later optimisation).
- Code layout: top-level `ghosts/` so both roots can import `@/ghosts/...` without tripping the isolation test. `ghosts/protocol.ts` (encode/decode/clamp, shared), `ghosts/room.ts` (pure room state machine: join, leave, accept(id, raw) → {deliver: [...], close?}, caps, token bucket; no I/O, fully unit-tested), `ghosts/worker/` (DO adapter `worker.ts`, `wrangler.jsonc`, own `package.json` with `wrangler` and `@cloudflare/workers-types` devDeps, own `tsconfig.json`). Root `tsconfig.json` and `eslint.config.mjs` exclude `ghosts/worker/**` (Workers globals); the root `npm ci` stays unchanged.
- Worker proof without credentials: `npx --yes wrangler@4 deploy --dry-run --outdir /tmp/ghosts-dry` ("Compile a project without actually deploying") bundles the DO with its binding config; optional local smoke `wrangler dev --local` against a node `WebSocket` client (not in CI). The fake server (below) runs the same `room.ts`, so the fan-out rules are proven in Node.

### Fake server (two-browser proof)
`scripts/ghosts-fake.mjs`: node `http` server, `upgrade` event, hand-rolled RFC 6455 handshake and text-frame codec (~80 lines, masked frames in, unmasked out, close/ping), driving `ghosts/room.ts`. Records every upgrade (origin, path, cookie header present?) and every accepted/dropped message; `GET /__probe/log` returns them; `POST /__probe/mode?m=refuse|full|flap` switches behaviour for negative controls. Fixed port from `GHOSTS_FAKE_PORT` (default 4790). Node 22 ships a `WebSocket` client global, so a node-level protocol test can also drive it without Chrome.

### Client
- Config at runtime, not build: `app/api/ghosts/route.ts` returns 404 unless `GHOSTS_ENDPOINT` is set (read per request behind `connection()`), else `{endpoint, rooms}` with `cache-control: no-store`. Reason: `NEXT_PUBLIC_*` is inlined at build, but CI builds once and the fake's port is known only at run time; and production can be switched on or off in Vercel without a rebuild. The site's `app/api` is outside every isolation rule, and the palace calls it by URL, not import.
- `ghosts/client.ts` (pure, tested): `shouldRun({reduced, hidden, hiddenPref, endpoint})`, `throttle(10 Hz, delta ≥ 0.002)`, `decay(trail, dt)` (12-point trail fading over ~700 ms), `lerp` tip, `backoff(attempt)` (3 tries: 1 s, 3 s, 8 s, then give up for the page lifetime), ghost expiry (a ghost silent 6 s fades out), `{t:"n"}` presence count.
- `ghosts/canvas.tsx` (client component, `dynamic(() => import(...), {ssr:false})` after `requestIdleCallback`): one fixed canvas, DPR capped 1.5 (reuse the `bufferSize` idea), brush-tip dots with wobble, fading trails, click ripples drawn as 2–3 jittered expanding circles (own ripple drawn immediately on `pointerdown`, others' on `{t:"c"}`). rAF runs only while at least one ghost is alive and the page is visible. Attributes as observables: `data-ghosts="<n>"` (others present), `data-ghosts-state="off|connecting|on|gone"`. A faint "N here" label only when n ≥ 1, in the corner, no sheet (inline style).
- Lifecycle: on `document.hidden` close the socket and stop rAF; on visible reconnect (new anonymous id, which is fine). Reduced motion (`prefers-reduced-motion: reduce`): no socket at all, nothing drawn, `data-ghosts-state="off"`; a `change` event re-evaluates. Offline / endpoint 404 / refused / `full`: nothing drawn, no error UI, at most 3 attempts, no console noise beyond Chrome's own connection line.
- Mount points: `app/(site)/(home)/page.tsx` → `<GhostsLoader room="/" />` from `components/ghosts-loader.tsx` (same pattern as `pond-loader.tsx`); `app/(ryugu)/ryugu/page.tsx` → `<Ghosts room="/ryugu" />` from `@/ghosts/canvas` (no `components/` import). Rooms: Home and the palace only for this part.
- Pocket: the preference module is `ghosts/pref.ts`, not `lib/` (the palace cannot import `@/lib`): `localStorage.ghosts` = `"hidden"`, parse/store, subscribe, `storage` event. `components/handheld.tsx` gets a chip `Ghosts: on/off` beside the Dive chip (`data-pocket-ghosts`, `aria-pressed`), menu mode only; turning it off closes any open socket in that tab and in other tabs via the `storage` event.

### Wiring for CI and e2e
- `scripts/e2e.mjs`: when it starts its own server, pass `GHOSTS_ENDPOINT=ws://127.0.0.1:${GHOSTS_FAKE_PORT??4790}/ghosts` and start `scripts/ghosts-fake.mjs` for the suite's lifetime.
- `ci.yml` "E2E against next start": start `node scripts/ghosts-fake.mjs &` before `npm start &` and export `GHOSTS_ENDPOINT` for the server. The fake stays up for the later probe steps, so no page logs a failed socket. Add the matching assertion to `scripts/ci-workflow.test.mjs`.
- `e2e/ghosts.test.ts` (one browser, two contexts A and B on Home; then the same on `/ryugu`): B's canvas reaches `data-ghosts="1"` after A moves; A's pointer path produces ≤ 10 messages/s in the fake log with 0 ≤ x,y ≤ 1 and no cookie header on the upgrade; A clicks → B draws a ripple (observable via a `data-ghosts-ripples` counter); A closes → B returns to `data-ghosts="0"`. Negative controls: fake in `refuse` mode → state `gone` after 3 attempts, no page error; `full` mode → `gone`, no ripple; reduced-motion context → state `off`, 0 upgrades at the fake; Pocket chip off → socket closed, 0 messages after; endpoint unset (`GET /api/ghosts` 404, driven by a second `next start` in a probe script, or by a `route.ts` unit test) → state `off`; a raw upgrade with `Origin: https://evil.example` → 403 at the fake, same as the Worker (shared `room.ts`/`protocol.ts` origin check).

## Privacy and cost boundaries
Nothing is stored (no DO storage writes, no KV, no logs); ids are per-connection random; payload is clamped numerics only; no text channel, so no moderation surface; no cookies cross to the Worker (different origin, no `credentials`); Origin allowlist; room and rate caps bound fan-out. Free plan suffices; `observability` off. Document in README "Deploying": optional Vercel Production env `GHOSTS_ENDPOINT`, and the Worker's `ALLOWED_ORIGINS` var.

## Risks and mitigations
- Chrome logs a refused WebSocket as a console error; later CI probes count console errors. Mitigated by keeping the fake up for the whole job and by `/api/ghosts` 404 meaning "do not even try".
- Hibernation drops in-memory state: keep per-socket id/token-bucket in `ws.serializeAttachment`, or accept non-hibernating DOs at first (cost is still near zero at this traffic). Prefer attachment; test the pure room with a reload round-trip.
- Empty-room problem: most visits see nobody; the label and canvas appear only when n ≥ 1, so the feature is invisible rather than sad.
- Viewport mismatch: normalized coordinates map approximately between sizes; acceptable for ghosts, document in copy ("someone, roughly here").
- pm-271 collisions in `handheld.tsx` and `ryugu/page.tsx` (fetch, add beside, re-run `npm test`, push fast).
- `wrangler` download in task 1's verification needs npm network (confirmed reachable from a pod; CI has it). If the registry is down, that single item is `cause=environment`, the node tests still prove the room.

## Decisions (advisory defaults chosen, recorded with plan_manager_record_decision)
Cloudflare DO over PartyKit/Supabase (no vendor layer, free, no storage); runtime `GHOSTS_ENDPOINT` + `/api/ghosts` over `NEXT_PUBLIC_*`; top-level `ghosts/` module so the isolated palace can share it; rooms Home and `/ryugu` only; reduced motion = fully off; hidden tab = socket closed; fake server dependency-free and sharing `room.ts` with the Worker; credential chore deferred to task 5.
