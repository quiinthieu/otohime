# Optional Lanyard games — pm-272/t-1566

Run run-9109 implements optional keyless game presence in the shared on-demand reader. The server selects a validated public Lanyard snowflake ahead of Steam; each configured provider's failures stay quiet. Music selection remains independent. Sanitization also preserves selected Lanyard as quiet if serialized state metadata is malformed, rejecting legacy Steam fields instead of switching providers. The public result keeps only a capped game title and a null URL, with Lanyard source/state metadata and credit. Both server-owned identity defaults remain empty. Optional owner activation is advisory.

The parser requires `success:true`, an object data envelope, and an activities array. It chooses the first type-0 activity with a valid name, ignoring malformed, Spotify, streaming and custom-status activities. It never publishes Discord identity, profile/avatar/friend fields, activity links or guessed store links. Valid empty activity is live (fixture on loopback); unknown users, bad envelopes/JSON/HTML, redirects, HTTP errors and aborts are quiet. The server requests JSON once with a meaningful User-Agent, a four-second abort and redirect rejection.
