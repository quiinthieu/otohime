## The failure

```
not ok - site: /projects, /sign-in and /does-not-exist load with no console error or page error:
  console https://otohime.dev/does-not-exist: Failed to load resource: the server responded with a status of 404 () | (same line, reduced motion)
probe: 278 ok, 1 failed
```

`scripts/probe-motion.mjs:288` excludes the 404 document's own load only when its text ends
`404 (Not Found)`. That is the HTTP/1.1 reason phrase, which local `next start` sends. HTTP/2
has no reason phrase, so Chromium writes `404 ()`:

```
$ curl -sI https://otohime.dev/does-not-exist        → HTTP/2 404
$ curl -sI --http1.1 https://otohime.dev/does-not-exist → HTTP/1.1 404 Not Found
```

The logged line has no `(source-url)` suffix, so it is the document itself, not a broken
subresource: the site is fine. I tried the fix (`404 \((?:Not Found)?\)$`) in a temporary copy
against production and got **279 ok, 0 failed, exit 0**. I then restored the file, and the tree
is clean.
