Every probe check passes on production except the axe item below. One
first-pass miss was the probe's own: it read the live region before React's
effect had run, and after 300 ms it read "Tokyo, 2026-10-20 21:15". The drag
checks confirmed the live region on every move.

The no-JS markup differs from task 2 (992bfb1) only by the slider attributes
on `<g data-disc>`, the empty `data-actions` mount, a `data-rim` marker, a
transparent `disc-hit` circle (`fill: transparent`, used for the focus ring
and drag target), and Sun and Moon groups that are always drawn but carry
`visibility="hidden"` when off the disc. None of these changes what a
no-JS visitor sees.

## Follow-up (non-blocking)

- **axe-core `nested-interactive` (serious, WCAG 4.1.2) at every viewport:**
  `<svg class="wheel" role="img">` (`app/(planisphere)/_components/wheel.tsx`)
  now contains the focusable `role="slider"` disc. Under ARIA, `img` has
  presentational children. Chrome still exposes slider "Hour" (checked in the
  CDP AX tree), but WebKit and Firefox may hide it. The form's hour range
  stays a fully accessible, synced hour control. Lighthouse (100) does not run
  this rule, so the plan's ≥95 bar is met. A fix could drop `role="img"` from
  the outer svg and keep its title and description on a `role="img"` group
  around the decorative layers, or give the svg `role="group"`.

  this run.
